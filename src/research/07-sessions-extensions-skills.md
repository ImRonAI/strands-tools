## Sessions, extensions, and skills

Live GitHub snapshot used on 2026-07-26: `strands-agents-extensions@4d07e66`, `strands-sqlite-session-manager@ee8f21d`, `strands-postgresql-session-manager@dfcbc1e`, `strands-redis-session-manager@192ba48`, `strands-supabase-session-manager@b9050aa`, `strands-valkey-session-manager@0edd4b7`, `sample-strands-agents-agentskills@c5564fc`, `strands-agentskills@0a56681`, `strands-skills@3807964`, and `hcls-agent-skills@48287b7`.

This grouping contains exactly the 10 requested repositories and 71 rows: 11 extension/session-manager implementation entrypoints, four skill-loader factories that produce model-facing tools, and 56 checked-in `SKILL.md` entrypoints. Session managers are lifecycle/storage integrations passed to `Agent(session_manager=...)`, not model-facing tools. Skill rows count one actual skill directory each, never its references, assets, scripts, tests, or evaluation prompts.

Repository integrity findings:

- `afarntrog/strands-agents-extensions` exports five plugins and one SQLite manager. Its manifest advertises a `dynamodb` extra but contains no DynamoDB session-manager implementation. Its SQLite manager is functionally the same implementation as the standalone `afarntrog/strands-sqlite-session-manager`, differing only in formatting.
- `hi-space/strands-agentskills` is archived and explicitly redirects users to `aws-samples/sample-strands-agents-agentskills`. Its two loader factories and its `file-processing` and `skill-creator` skills are duplicates of the AWS sample; they remain separate rows because they are live entrypoints in a separately requested repository.
- The AWS sample's Python package installs loader code, but its `skills/` directories are repository content rather than declared package data; use the repository checkout when loading the bundled skills. Its PPTX skill also checks in `node_modules` and `__pycache__`, which are generated artifacts, not additional skills.
- `kyopark2014/strands-skills` has 11 live skills. Its README advertises `seoul-subway`, but no corresponding `SKILL.md` exists; conversely, live `browser-use` and `graphify` skills are omitted from the README catalog. Several skill-specific dependencies (`browser-use`, `graphifyy`, `pypdf`, `openpyxl`, document/presentation Node packages, LibreOffice) are absent from the repository's Python requirements.
- `awslabs/hcls-agent-skills` has 40 live skills, matching its README badge/catalog. The installer help still says "all 38 skills" and its Quick Desktop list references absent `proteomics-analysis`; neither string creates an additional skill. The repository `pyproject.toml` packages the evaluation harness, not the skills themselves.
